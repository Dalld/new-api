# 推荐计划安全审查记录

日期：2026-08-07

## 已确认的实现

- 管理员手动绑定邀请人仅允许 Root 调用。
- 手动绑定仅可在用户尚未绑定邀请人时执行，且不会补发注册奖励。
- 充值返利通过事务与 `TopUpID` 唯一约束结算，未发现重复结算风险。
- 邀请额度转入使用事务、行锁和余额检查，未发现并发重复转入风险。
- 用户端邀请记录与返利记录已对被邀请用户名做脱敏处理。

## 上线前风险

当前公开注册会立即发放注册送额度、邀请人奖励和被邀请人奖励。邮箱验证、Turnstile 和基础接口限流只能提高批量注册成本，不能可靠阻止代理池和临时邮箱批量套取余额。

普通管理员还可以读取全站推荐关系和充值返利明细，其中包含不必要的邮箱、邀请码、订单号和充值金额数据。

## 建议的后续方案

推荐采用“首笔有效充值后解锁”规则：注册时只建立邀请关系；被邀请用户完成首笔成功充值后，在同一幂等结算流程中一次性发放被邀请人赠送额度和邀请人奖励。该方案应配合以下措施：

1. 在生产环境启用并正确配置 Turnstile。
2. 保持邮箱验证开启，并对验证邮件发送实施独立限流。
3. 将全站推荐关系和返利明细接口收紧为 Root，或实现独立财务权限并最小化返回字段。
4. 对邀请额度转入增加正数与账户余额上限校验，拒绝溢出值。
5. 不向客户端或普通日志透出原始数据库错误文本。

该方案尚未实施。它会改变注册奖励到账时机，需在确认业务规则后单独开发、测试并部署。
